> [!NOTE]
> 这是一篇阶段性的闪念笔记，用于梳理几种 Agent 工具调用方式之间的关系。

Function Calling 提供了基础的工具调用能力。

MCP 在此基础上提供了标准化的接驳方案，解决了 Agent 与既有系统之间的工具接入问题。

Skills 则提供了一种使用文字定义流程、沉淀操作经验的方案。

## Function Calling

**作用：决定选择哪个工具。**

Function Calling 是一种工具调用协议。开发者向模型提供工具信息，模型根据任务判断是否需要调用工具，以及应该选择哪个工具。

它让模型具备了从“生成文本”走向“调用外部能力”的基础。

## MCP

**作用：统一工具格式，提供工具接入标准。**

一个工具通常需要描述以下信息：

- 名称
- 功能描述
- 参数格式

### 工具来源

MCP 中的工具可以来自：

- 自己编写并注册的代码
- 平台内置工具
- 第三方提供的 MCP Server

### 优势

1. **更可控**

   一条 CLI 命令中如果包含很多步骤，一旦执行失败，错误往往不容易定位。拆分成结构化工具后，可以更明确地观察每一步的输入、输出与执行状态。

2. **更安全**

   一条缺少约束的 CLI 命令可能对系统造成较大影响。结构化工具可以限制参数、权限和允许执行的操作范围。

### 相对劣势

1. **Token 消耗较大**

   工具的名称、描述和参数格式等信息都需要进入上下文。当工具数量很多时，会占用较多 Token。

## CLI

**作用：通过命令行调用本地工具。**

CLI 是一种本地执行工具的调用方式。Agent 可以通过命令行直接使用操作系统或开发环境中已有的程序。

### 优势

1. Token 消耗相对较小
2. 执行效率高
3. 可以直接复用成熟的系统工具与开发工具

### Bash 做了什么？

Bash 可以理解为解释器与调度器，它主要完成三件事：

1. 解析输入的命令
2. 找到命令对应的程序
3. 执行程序并返回结果

CLI 工具通常来自：

- 操作系统自带工具
- 第三方安装的软件
- 自己编写的脚本

## Skills

Skills 提供了一种用文字定义流程的方式，可以把完成某类任务所需的步骤、规则和经验沉淀下来，让 Agent 在合适的场景中复用。

## 简单总结

- **Function Calling**：让模型能够选择并调用工具
- **MCP**：让不同工具以统一标准接入 Agent
- **CLI**：让 Agent 直接调用本地程序和系统能力
- **Skills**：将可复用的任务流程和操作经验沉淀为文字说明
